The workspace adapts to the material you are reviewing. HTML gets a rendered canvas; files and diffs add navigation for moving through the publication.

## Arrange the conversation

On desktop, use the discussion control in the navigation bar to show or hide the dock. It restores the last expanded or floating mode. Both visible modes also provide a **Hide** control inside the panel.

Hiding the dock gives the content more room. You can still begin a targeted note through the floating composer. Draft text and its target survive view changes.

## Move through files

Use the file panel or **Jump to file** to reach a document directly. Fold sections you are not reviewing, mark a file viewed, and move to the next one. The displayed file stack and navigation refer to the same captured version.

Large source files and diffs mount visible rows progressively. **Locate** can unfold and load the target before jumping to it, so you do not have to scroll manually to wake up a distant section.

For diffs, switch between unified and side-by-side layouts. For HTML or Markdown inside a files artifact, choose rendered or source view. These controls are intentionally absent from an HTML artifact’s rendered-only workspace.

## Review on a phone

On small screens, the conversation opens in a discussion sheet while the content remains the main reading surface. The toolbar and touch controls provide the same review state as desktop. Targeted drafts stay attached to their original context when you move between content and conversations.

Use the page’s own controls to explore an HTML artifact, then switch to comment mode to anchor feedback. A wide code block or patch may need horizontal scrolling within its pane.

## Appearance and keyboard controls

Use the workspace’s appearance controls for light/dark presentation and source highlighting themes. A published page can supply its own design, so its colors need not match the surrounding workspace.

Open the visible keyboard-shortcuts control, or press `?`, to see the current bindings. Shortcuts stand down in text fields and overlays, and hidden discussion controls do not keep invisible actions active. See the [generated keyboard reference](/docs/keyboard/) for the complete map.
