# Browser and website localization

English (`en`) and Simplified Chinese (`zh-cn`, HTML language tag `zh-CN`) are
available. **The Chinese catalogs and Markdown files currently contain English
placeholders.** Translate their values/content; do not rename the keys.

## Translation files

| Surface | English source | Chinese placeholders |
| --- | --- | --- |
| r3 web UI, including demo chrome | `web/src/locales/en.json` | `web/src/locales/zh-cn.json` |
| Website shell, landing pages, metadata, diagrams, captions and browser controls | `site/locales/en.json` | `site/locales/zh-cn.json` |
| Website articles | `site/content/*.md` | `site/locales/zh-cn/content/*.md` |
| Generated reference pages and landing-page Markdown exports | `pageSource` / `landingMarkdown` in `site/build.ts` | `site/locales/zh-cn/reference/*.md` and `site/locales/zh-cn/content/{home,use-cases}.md` |

JSON keys are English source messages. Empty or missing values fall back to the
English key. Keep every `{namedPlaceholder}` exactly as written; its position
can move. `Trans` messages use some placeholders for inline React elements,
including links and code. Translation values are text, never HTML.

Keep both singular and plural message keys. The UI selects the form with
`Intl.PluralRules`; Chinese uses the other form for all counts. Do not translate
commands, IDs, paths, keyboard chords, template variables, or sample code.
Markdown can retain authored HTML and `<!-- visual: name -->` markers. Preserve
heading order: the builder assigns English heading IDs to translated headings
so links and language switches retain their destinations.

Published documents, artifact titles/summaries, comments, source code, demo
publications, and server/CLI diagnostics retain their authored language. Browser
controls and client-authored errors are localized. CLI help, agent prompts, HTTP
fields and persisted domain values are outside localization.

## Runtime behavior

r3 chooses a supported `?lang=` value, then its saved `r3-locale` preference,
then the browser's supported language preference, then English. Settings and
the login screen expose a language selector. Switching updates subscribed
components, document language, date/number formatting and preview annotation
controls without remounting the workspace. Other tabs follow saved changes.
Unavailable storage leaves the choice usable for the current page.

App hosts call `initializeLocale()` before mounting. Importing reusable controls
does not take ownership of the enclosing document's language. The trusted parent
sends translated annotation labels over the existing preview display channel;
published documents do not receive preferences or new capabilities.

Website English URLs stay unchanged; Chinese pages live under `/zh-cn/`.
The URL selects the language, including without JavaScript. Header links (inside Menu on phones) switch
the equivalent page and preserve the query/fragment. Navigation, Markdown
downloads, canonical/alternate links, sitemap and Pagefind searches follow that
language. Assets and the interactive examples are shared; example links pass
the chosen language to the app. Screenshots and videos remain their original
recordings.

## Adding copy and checking translations

For app copy, use `t`, `plural`, or `Trans` and add the source key to both JSON
catalogs. Components computing translated strings subscribe with `useLocale()`;
keep translations out of module-level constants and include locale in memo/effect
dependencies when they compute or send display text. Translate display labels
at their use site, keeping wire values and authored content unchanged.

For static website copy, run `bun --no-env-file site/build.ts --sync-locales`
after editing English templates. It adds discovered source text to the catalogs
while preserving existing Chinese values. Add browser-script messages to both
catalogs alongside their `t()` calls. New articles need a corresponding Chinese
Markdown placeholder. Normal builds do not rewrite translation files.

Run `bun --no-env-file test web/src/i18n.test.ts site/i18n.test.ts` for locale
fallbacks, catalog/placeholder parity, safe static text and stable heading IDs.
After building the site, run `site/check-i18n.ts` with `R3_TEST_BROWSER` set.
It uses temporary marker translations and fresh browser profiles to check real
UI switching, cross-tab persistence, draft retention, mobile layout and localized
search. Use the same `R3_SITE_BASE` as the build. Finish with the repository's
normal typecheck, tests, formatting and builds.
